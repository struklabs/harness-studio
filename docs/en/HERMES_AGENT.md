# Connect an Agent and Complete a Task

[Türkçe](../tr/HERMES_AGENT.md)

Harness integrates **Hermes Agent by Nous Research**. Open Modules → Agents. Inspect the installation permissions, install if needed, start Harness Gateway in Settings, select a chat model, and choose Connect. Enter a simple question and choose Run Task. Stop terminates the Harness-owned task process tree. Disconnect restores the original configuration and revokes the connection's token. Removal disconnects and removes the managed runtime while retaining external installations and user data by default. Use the module controls to update, repair, roll back, or remove managed files; review deletion choices before confirming.

Simple mode shows the connection and task controls. Advanced also shows executable/configuration/backup paths and installer output. Failed installation output is visible in either mode. Model recommendations reuse native tool-call evidence and hardware fit estimates; unverified template support is labeled as such. Linked chat aliases can also be selected (marked Remote), but local hardware recommendations apply only to local files.

## Installation and Compatibility

Harness downloads and executes the official `https://hermes-agent.nousresearch.com/install.ps1` on Windows or `https://hermes-agent.nousresearch.com/install.sh` on POSIX. It passes the upstream noninteractive, skip-browser, and skip-computer-use options and runs only the selected backend stages in the managed runtime directory. The source commit is pinned; the bootstrap script is not hash-pinned. It does not fork Hermes, run onboarding, configure messaging, or install a service. Upstream downloads and prepares its own dependencies; installation approval permits this installer to run with the user's privileges. It is not a hash-pinned Harness runtime, and the download/disk sizes are estimates. Source-build dependencies may be required. Installation output is bounded and cancellation kills the installer process tree. The install runs as a background job (it can take ten minutes): the Install action returns at once, the module reads Installing while it runs, and the module list shows the final state. If it fails, the partial files are removed and the installer output is kept in the Harness logs folder as `agents-install.log`.

Detection checks PATH and standard source-install launcher locations, probes `--version` with a deadline, and reports missing bootstrap commands or a broken/missing Python API runtime. Version probes are cached briefly. Launchers named `hermes.exe`, `hermes.cmd` (the command file upstream writes when it has no native launcher) and `hermes` are recognised. Source installations using the current PM launcher and legacy virtual environments are supported. Desktop-only bundles without a discoverable source/API runtime are reported as missing that dependency; use the official source installation. Harness-managed runtime updates use the bundled version and module update controls. External source installations keep their own upstream update workflow.

## Connection, Permissions, and Recovery

Connect previews the running local Gateway address and chosen model. It creates a named token using the existing token store: only `inference`, exactly the selected model alias, and only chat/model-list endpoint groups. No control, tool, shell, or admin scope is granted. Keys never enter IPC or process arguments. The agent needs its token in its own private configuration; Harness stores only its salted token digest and connection metadata. On a Gateway that accepts tokenless loopback calls, other local clients can still bypass token policy; enable the local token requirement to make restrictions binding for all clients.

The complete original configuration is saved privately as `config.yaml.harness.bak`. A private `harness-connection.json` journal is written before the atomic configuration replacement; corrupt YAML and existing backups are refused. Unrelated settings are retained. Disconnect revokes first and restores the original bytes, or removes a config that did not previously exist. If another interface edited the config, restoration refuses to overwrite it and retains the backup/journal for recovery. Inspect the backup, restore its bytes to `config.yaml`, then retry Disconnect. An orphan backup from interrupted cleanup must be inspected before reconnecting.

Harness tasks use a temporary Hermes home, explicit local model credentials, a cleared credential environment, and no user context/memory/skills/hooks/MCP configuration. Each run requires a fresh grant in the UI. By default `enabled_toolsets=[]`: inference only. Optionally grant up to eight absolute folder paths to the read-only `harness_read_file` tool. It resolves symlinks/junctions before checking folder containment, accepts only regular files, and limits each read to 32 KiB. Execution fails closed unless upstream exposes exactly the granted tools. Shell, writes, and additional network access cannot be granted. Sensitive actions and interactive approvals are unavailable in this adapter, rather than silently approved. This is an application-level restriction, not OS sandboxing of trusted upstream Python code. Other Hermes interfaces retain their own permission rules. Output is bounded to 64 KiB and the task token is redacted. Tasks have a ten-minute deadline, at most four iterations and 512 generated tokens per iteration.

## OpenClaw

Choose **OpenClaw** at the top of Modules → Agents (the agents module must not be disabled). Connection, scoped token, task history, per-run permission, audit and Stop work as described above; the differences are:

- **Installation.** Harness detects an existing `openclaw` on PATH, in the npm global folder, or in its own folder. If none is found, **Install OpenClaw** runs the official upstream method, `npm install --global openclaw@<version>` (with `--allow-scripts=openclaw` on npm 11.16 or newer), into a private prefix under the Harness data folder: no global command, PATH change, background service or onboarding wizard. The release is pinned; it needs Node 24.16+ (24.x) or 26.1+ and npm, and the missing or outdated tool is listed. **Remove Harness Installation** disconnects first and deletes only that private folder; an OpenClaw installed elsewhere is never removed.
- **Configuration.** OpenClaw keeps `openclaw.json` (JSON5) in `~/.openclaw`, or where `OPENCLAW_STATE_DIR` / `OPENCLAW_CONFIG_PATH` point. Connect saves the file as `openclaw.json.harness.bak`, journals the change, adds a `harness` provider (`api: openai-completions`, the local Gateway `/v1` address and the scoped token) and sets `agents.defaults.model.primary` to `harness/<model>`. Other settings are kept. Comments and trailing commas are read; other JSON5-only syntax is refused without touching the file, and the comments of the original survive in the backup, which Disconnect restores byte for byte (with the same external-edit protection as Hermes).
- **Tasks.** A task runs `openclaw agent exec` with a temporary config, state folder and home folder, so channels, plugins, hooks, MCP servers and your own `~/.openclaw` are not read. Without a grant no tool is available. One granted folder becomes the workspace and enables only the `read` tool, restricted to it; shell, writes, browser and web tools are denied. OpenClaw accepts a single read folder. The answer and token usage come from the `--json` result; diagnostics are shown only when the run fails.
- **Models.** The same chat model list is used, including Harness Link models, which are marked Remote.

## Harness Link Models

Chat models served by another Harness through Harness Link appear in the model lists of Hermes, OpenClaw and Paperclip, marked **Remote**. There is no local file, so no hardware fit or recommendation applies to them, and their tool support is unverified. The scoped token allows exactly that model id (for example `remote:<link>/<model>`), only the chat and model-list endpoint groups, and the Gateway forwards the request to the linked Harness. Ids that contain `*` or `?` are refused.

## Task History and Audit

Harness stores its own private `agents/history.json` under the app data root. It lists running and past Harness tasks with the model, prompt, start/finish times, duration, token count when reported by upstream, errors, and reopenable output. Runs also record the granted folders, tool calls/denials, and start/stop events. A run left running after an app interruption is marked Interrupted on the next history read. Delete History Entry removes only that Harness entry and its audit/output; it never edits Hermes sessions, databases, configuration, or user files. Running entries must be stopped before deletion. External Hermes sessions are not imported. Treat saved prompts/output as private user data.

## Existing Paperclip Instances

Generate Configuration creates a separate, named Paperclip inference token restricted to the selected local or Harness Link chat alias and chat/model-list endpoints. The Gateway must require tokens. Inspect/copy the endpoint and configuration; the plaintext credential is shown only in this handoff and is not saved in Harness history. Revoke it here or in Settings. The endpoint must be reachable from Paperclip's agent execution host; loopback requires the same host.

Automatic Apply targets an **existing `opencode_local` agent** in an existing Paperclip instance. It uses the documented [GET/PATCH agent API](https://github.com/paperclipai/paperclip/blob/master/docs/api/agents.md) and [per-agent environment configuration](https://github.com/paperclipai/paperclip/blob/master/packages/adapters/opencode-local/src/server/execute.ts), with OpenCode's documented [inline config](https://opencode.ai/docs/config/#precedence-order) and [OpenAI-compatible provider](https://opencode.ai/docs/providers/#custom-provider). Apply preserves unrelated adapter settings, environment entries, inline permissions and other providers; it updates the selected model and the `harness` inline provider. Malformed or secret-reference inline configuration is refused instead of overwritten. HTTPS or loopback HTTP is required; redirects are disabled. API credentials are used transiently and response bodies are not exposed in errors. Paperclip retains its own execution/tool permissions. No installation, startup, updates, or other lifecycle management is performed. Other adapter types can be configured manually using their supported OpenAI-compatible settings; Apply does not guess their schema.
